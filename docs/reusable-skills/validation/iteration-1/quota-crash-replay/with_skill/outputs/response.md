# 场景推演：图像描述 API 的额度与崩溃重放

本方案依据 ai-usage-idempotency 技能及案例设计，未修改产品、运行测试或调用供应商。

## 身份和计量

把鉴权后的立即扣额改为授权检查、额度预留、执行与校验、原子结算。成功定义为上游完成且描述通过结构和业务校验；不是 HTTP 成功即可扣额。预留占用可用余额但不形成最终用量，以免不同键并发穿透余额。确定失败释放预留、用户不扣；不确定执行单列状态，不谎称供应商未收费。

操作唯一域为认证用户＋功能＋稳定操作键；不要信任请求中的任意 userId。保存请求摘要，覆盖图像实际内容、影响结果的参数和协议版本，不能只摘要可变图片 URL。原操作重试沿用键，新图必须换键。同键异摘要返回冲突；跨用户同键隔离。摘要是敏感派生数据，不是匿名化；键、日志均不含图片、凭证和描述正文。

## 三个 worker 的协调

建立持久化 Operation，含摘要、状态、预留、执行者、租约/代次和结果引用。数据库唯一约束保证一个操作记录；用短事务锁定操作及额度记录，完成抢占与预留后才允许执行。其余 worker 返回处理中或复用结果，不能再发上游。进程 mutex 和缓存只作优化。

校验成功后，在同一事务中保存可恢复结果或其可靠引用、插入唯一 UsageEvent、扣减余额、释放预留并标记成功。唯一事件约束和状态条件更新防止重复结算；代次检查防止旧 worker 覆盖新状态。租约过期不能直接证明上游未执行，不能由接管者盲目重发。

## 重放和事故处理

| 状态 | 原键重试行为与计量 |
| --- | --- |
| 在途 | 返回处理中及查询入口，不再执行、不重复预留 |
| 成功且结果仍在 | 鉴权并核对摘要后重放，不再扣额；余额耗尽也可取已有结果 |
| 确定失败 | 不扣用户额度；可按错误类型恢复原操作，但须先确认没有不明执行 |
| A：上游成功、本地提交前崩溃 | 持久记录转为结果不明，暂停自动重试。若没有可验证的耐久结果，不能自动结算成功；按明确时限释放预留，记录平台潜在成本 |
| B：已提交用量、结果丢失 | 返回“已结算但结果不可恢复”，不重新扣、不自动调用。若有耐久结果则直接恢复；若确实丢失，可按产品规则补偿一次并记录唯一补偿事件 |

A 无供应商幂等键或历史查询，无法保证上游恰好执行一次。即使先持久化结果，调用完成到持久化之间仍有窗口。用户明确重新生成时创建关联的新操作，说明可能再次调用及其额度规则；不能将此称为原请求安全重放。用户失败不扣额度与供应商是否收费是两套账。

结果持久化应限定账号权限、加密与保留期限，删除后保留最小计量凭据并明确结果不可重放，避免以缓存名义长期存图。

## 待执行验证
