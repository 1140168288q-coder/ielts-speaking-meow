## 2. 质检过程发现的问题与修复记录

最后一页复检：架构图简化为界面、本地能力、后端、模型与数据库四层阅读顺序；图内 HTML 标签转为原生 SVG 文字，避免字体度量差异造成末尾裁切。HTTPS 标签增加白底，避免连线穿字。正文增大字号与行距，源码出处分行，代码允许安全换行。重新渲染后核对节点、代码和页脚均完整，全文仍为 10 页。

1. **问题 1：Chrome headless 导出时的页数浮动风险**
   - *现象*：部分浏览器打印引擎由于边距和外边距计算可能产生微小舍入误差，导致最后一页溢出一小段空白内容产生额外空白页。
   - *修复措施*：在 CSS 中将 `.page` 容器设定为固定高度 `height: 297mm; max-height: 297mm; overflow: hidden;`，同时对内部 `page-content` 采用 flex 自适应排版，将内边距精确控制为 `13mm 17mm 11mm 17mm`。新增架构页后重新生成，稳定为 10 页。

2. **问题 2：代码中关键字与模板占位符的检查冲突**
   - *现象*：初版质检脚本中将 `undefined` 纳入通用占位符列表，但在扫描第 6 页代码选材 C01 时报 `undefined` 警告（`material !== undefined`）。
   - *修复措施*：核验该行代码属于 `src/domain/trainingPlan.ts:104` 的真实 TypeScript 语法，并非文档模板漏填；优化了质检脚本，将代码语法保留字与模板占位符明确分离，确保质检纯净。

3. **问题 3：贯穿案例的语义混淆预防**
   - *现象*：初稿排版中，若将 AI 双参考版本与用户第二答排在同一纵列，评委容易误以为自然提升版是用户的回答。
   - *修复措施*：在第 4 页采用左右对称对比看板，左侧绿/红强调“用户作答（一答原貌 vs 二答进步）”，右侧蓝/紫强调“AI 参考版本（简单优化版 vs 自然提升版）”，并在底部用警告条明确声明“AI 参考版本不等于用户成果”。

4. **问题 4：构建产物与真机验收混为一谈**
   - *现象*：旧版同时写“真机实测通过”和“完整真机验收待完成”，无法从文档判断实际验证范围。
   - *修复措施*：P8 区分 Release 安装包与团队提供的真机实测信息，限定设备及公网服务条件；P9 将断网、其他机型和真实用户试用列为后续验证。

5. **问题 5：真实软件橙色主题校准与申报团队名称规范（ONE HARNESS）**
   - *现象*：历史基线审查图片与早期 CSS 配色带有早期版本的薄荷绿倾向（`#2E7D32`、`#E8F5E9` 等），而实际交付的 V2.2.2 真实软件全面采用陶土暖橙主色（`--ds-primary: #B7441E`、`--ds-primary-soft: #FFF0E6`）；同时申报团队名称需规范为官方团队名“ONE HARNESS”。
   - *修复措施*：
     1. 全书彻底消除绿色系修饰代码，CSS 与流程图色块全部校准为陶土橙/暖蜜桃/炭黑系（`#B7441E`、`#C2521B`、`#FFF0E6`）；
     2. 6 张核心截图逐一标注来源与处理方式；S02 已换成现有暖白橙色反馈界面原图，仅在 PDF 版面中裁切，不再展示黑色界面；
     3. P1 封面页眉、P9 团队专栏、申报单位及页脚等所有团队名统一更新为“常州工学院 · ONE HARNESS”，成员标明夏王恩（负责人）、沙飞扬。
