# 个人事实的来源、确认和生命周期

以下仅为场景推演与修复设计，未读取真实用户资料、运行产品或调用模型，验证项均待执行。

模板 ID 存在只能证明引用指向一个对象，不能证明对象中的经历属于当前用户。模板中的“I managed a team of 20”是示例；用户明确说从未管理团队，且说明这是朋友的示例。因此“曾管理20人”既归属错误，又与直接陈述冲突，必须停止用于个人画像和后续建议。

先阻断模板、AI 生成内容直接写入事实表的路径，将已有错误条目标为不可用，追踪其派生摘要、检索结果及缓存并清除；保留必要的脱敏修复记录，不把错误文本继续留在可检索日志中。不能只修正卡片，因为模型上下文可能仍包含错误资料。

沿用本地关系库即可。为来源保存 ownerId、资料类型、原始片段位置与版本；候选事实保存主语归属、命题、否定/假设等语义标记、来源关联、确认状态与时间。来源类别至少区分用户直接陈述、导入模板、第三方经历和 AI 示例。检索先按账号和状态过滤，再使用全文或关键词检索；不足 200 条资料没有引入向量库的必要。

模型只能提出候选，服务端校验来源是否存在、属于当前账号、片段是否匹配，并检查来源是否允许支持个人事实。引用有效性、语义支持和用户确认是三项不同条件；不能用一个真实 ID 或置信度阈值替代后两项。明确否定、他人、假设、引用文本应优先排除，冲突候选进入待处理状态。

本例不应再弹出“是否保存曾管理20人”。界面可说明已撤下错误记录，并展示原因和来源。若确需长期保存用户的真实情况，可单独询问“是否记住：你目前没有管理团队的经历？”，提供编辑、确认和不保存；默认不勾选。拒绝不能影响普通任务，也不能在下次自动重新生成同一候选。单次纠错确认不等于授权收集所有未来个人信息。

关闭 Memory 应立即停止候选抽取、事实写入、检索注入和自动更新，普通资料处理仍按其独立功能执行。清空已经组装的 Memory 上下文，并阻止在途请求返回后补写。说明关闭会保留已有资料，另提供查看和删除入口；重新开启不得自动追溯吸收关闭期间的对话。

删除事实要同步失效关联摘要、缓存和派生候选，删除来源时提示关联事实并按既定规则清理，避免再次导入自动复活。若存在同步或备份，需传播删除标记，并明确备份保留期限。切换账号时清空内存上下文，在查询和提交两端校验 ownerId，拒绝旧账号在途结果写入新账号。

验收正例：用户直接说“我管理过 3 人”，经独立确认后仅本账号可用。反例覆盖模板第一人称、朋友经历、否定、假设、AI 示例、合法 ID 但片段不支持、跨账号 ID，均不得成为事实。另验证关闭期间无读取或写入、删除后检索与恢复不复活、切号及在途请求无串号。只有这些行为实际通过后，才能声称修复有效。
