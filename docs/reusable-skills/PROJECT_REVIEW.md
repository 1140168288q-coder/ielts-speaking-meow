# 制作过程回顾与当前实现

## 证据范围

回顾覆盖仓库最早可见提交 `f7fed36`（2026-08-09）至 `e15d7a2`（2026-09-19），以及截至2026-09-20可见的项目材料。项目最初构思之前的讨论未完整覆盖；没有记录的决策动机不补写。这里的“最终实现”指该基线的实际实现，不意味着所有目标环境、用户效果或未来计划已经验收。

依据顺序：对应版本的提交快照解释历史；当前源码和测试定义解释现状；带日期的交付报告说明当时验证；计划文件只说明意图。部分当前发布文档被后续改写，不能单独用来还原旧版本。

## 1. 先建立本地训练闭环：V1.0—V1.1

2026-08-09，`f7fed36`建立Android练习基线；2026-08-10，`8972391`增加导入与独立AI Provider。初期流程包含录音、回放、转写和两次练习，本地记录与个人表达形成持久成果。

**做法与影响：**先把用户任务串起来，再让AI成为增强能力；通过Provider边界隔离外部服务，为后续换方案保留空间。初期计划还把Android真机硬化列为下一步，因此“工程已有实现”不等于“当时全真机验收完成”。

**迁移经验：**核心闭环必须有用户行动和保存成果；外部服务不可用时如何继续，要在一开始设计。对应 `core-loop-scope`、`interruptible-provider-fallback`。

## 2. 外部能力进入后端，并修复状态与降级：V1.2—V1.5

2026-08-13，`1f1286c`加入FastAPI、DeepSeek与火山语音服务，随后`394ec2e`处理WebView/browser跨域及健康版本信息。2026-08-15，`9121ec5`交付V1.5的后端状态透明与语音回退。

历史V1.5记录的返工包括云端长等待、实际未播却显示播放、改变音色仍用旧缓存。最终逐步建立独立供应商配置、真实操作状态、备用执行路径、输出相关参数缓存键，以及统一播放协调。

**迁移经验：**“配置存在”“请求可达”“实际执行成功”是不同信号；降级要真的执行备用能力；停止和切换不能被长任务锁住。对应 `ai-contract-reliability`、`interruptible-provider-fallback`。

## 3. 调整交互方式并完整退役旧能力：V1.6—V1.7

2026-08-18，`7c09acc`扩展参考回答、跟读/发音相关复盘和二答收录；同日`b93a696`转向文本提交、手动计时，移除应用内STT。用户改用系统键盘语音输入或手动输入。

退役涉及UI、Provider、后端路由、环境变量、依赖与设备权限；同时保留历史录音读取。当前新流程不产生应用内录音、不评价语音表现、不输出Band分数。

**证据边界：**可以确认移除与替代方式；没有找到足以证明“因为识别率差”或“为了节约成本”等具体动机的记录。`b93a696`当时仍是三个参考答案及`improvedAnswer`；当前V1.7文档已被后续更新为双版本，不能倒推当时即如此。

**迁移经验：**功能退役是一条完整迁移链；停止新写入不等于删除旧数据；已授权的产品简化应改掉旧测试与入口。对应 `core-loop-scope`。

## 4. 内容工程、账号与轻量个性化：V1.8

2026-08-19，`dd2d01e`引入结构化季度题库、本地账号、教学RAG、长期Memory与简洁反馈；`cd99a0f`补充工具卡住时的自救协议。

题库成为可再生的解析产物，保留Part、主题、新旧、cue points和题目关联。RAG使用小型本地语料与确定性匹配，Memory从真实持久化记录组织。账号开始为数据提供owner范围。

**重要返工：**早期题库解析器曾在缺cue points时补通用句，对关联/数量异常只警告；当前改为拒绝不完整来源内容。合法结构不代表来源忠实，不能靠生成文本把错误填平。

**历史校正：**`dd2d01e`快照只预留云同步身份，尚未实现同步；当前V1.8文档提到的云同步来自后续修改。

**迁移经验：**先用数据规模匹配的检索；对可更新内容建立来源、解析、校验、审阅和生成边界。对应 `source-import-pipeline`、`grounded-rag-memory`、`agent-delivery-handoff`。

## 5. 从本地应用扩展为受控云端产品：V2.0—V2.1.x

2026-08-23先保存改动检查点；2026-08-24，`25f8bc4`完成V2重构，`0c7d1cb`推进前端P0—P2改造。后续提交处理Windows部署、旧PowerShell兼容、Tunnel输入、邮件配置、TTS与同步兼容。

最终形成React页面、应用用例、domain契约、ports和infrastructure分层，以及FastAPI身份、同步、计量和供应商适配。加入正式邮箱账号、验证、手动同步、plan/entitlement/quota；真实支付仍不在范围内。

**迁移经验：**本地身份和云端身份需要显式绑定，登录不应偷偷上传；服务端数据归属来自认证身份。部署必须从真实主机、运行环境和网络证据出发。对应 `local-first-sync-recovery`、`public-stack-recovery`。

## 6. 把AI输出接回用户行动，并修复整条链路：V2.1.9—V2.2.0

2026-09-01，`f292039`对应2.1.9发布；2026-09-02/05，`146f718`、`f12f456`修复结构化反馈和超时重试。两种参考答案最终明确分工：简单版保持原意，自然版可以结合相关资料与明确标记的示例；第二次回答独立分析、确认表达及Memory。

实际问题不止提示词：Provider方法丢失this导致根本不发请求；共享in-flight状态吞掉二答；客户端比后端先超时；失败提前扣额；修正草稿未正确初始化。对应修复包括真实适配器测试、独立阶段状态、显式排队、分层总预算、成功后结算与稳定草稿。

2026-09-07，`07f2ba1`进一步增加会话原子更新、迟到结果快照保护、备份扩展、幂等请求摘要和短期结果缓存、完成后复盘及可解释训练计划。

**演进不能混写：**早期同键重试可能再访问上游；最终增加执行前已结算检查。最终也不等于所有崩溃窗口都实现端到端恰好一次。历史报告明确还有冲突解决入口、真机与部分环境未验收。

**迁移经验：**需要同时处理契约、状态、数据和成本，单改提示词无法覆盖整条可靠性链。对应 `ai-contract-reliability`、`async-workflow-integrity`、`ai-usage-idempotency`。

## 应保留的局限

- Memory词面来源检查是启发式；合法引用不等于语义真实。
- 个别实体更新有事务，不代表语料、Memory、整个备份都在一个全局事务里。
- 同步保留冲突不等于具备完整冲突解决界面；应用变更与推进游标分离时依赖可重放设计。
- 幂等缓存丢失后可能无法返回原结果；上游成功而本地提交前崩溃不能轻易承诺恰好一次。
- 文档中的Linux目标、历史真机验收计划及当前线上可用性，不能由现有源码和旧测试一概认定完成。
- 案例规模和参数是设计背景，不能机械复制为其他项目的最佳实践。
