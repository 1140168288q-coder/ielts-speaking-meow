# 场景推演：职业助手的来源与记忆修复

本方案依 grounded-rag-memory 技能及案例设计，未修改产品或执行验证。

## 修复流程

“曾管理20人”应撤出有效画像并使派生摘要失效。模板 ID 存在只证明引用可定位，不能证明人物是当前用户；原输入明确否定管理经历，且声明模板用于朋友。也不能进一步断言朋友确实管理过20人。排查同来源产生的事实候选，暂停自动入库，让用户审阅已有错误记录。

将模板/参考知识、当次输入、已确认事实、AI 示例分开保存。模板第一人称只能用于展示结构和写法；当前输入可产生候选；只有用户独立确认的内容能升级为事实。历史模型输出和画像摘要不能循环充当证据。检索文档中的命令也只是数据，不得授权跨账号读取、外发或写入事实。

导入按读取、提取、草稿、预览编辑、确认、事务保存进行。保留账号范围来源 ID、摘录、段落、提取方式与版本；草稿不提前进入检索。资料不足200条，先沿用关系库做主题与关键词检索，过滤当前账号、未删除且已启用条目，并返回匹配理由。分别组装参考知识与确认事实，设条目数和文本预算，以样本评估召回率后再决定是否需要向量库。

请求只带必要 task、inputVersion、knowledgeContext、confirmedFacts 和来源白名单；用户身份从认证上下文取得。返回引用须属于本次发送范围且类型匹配，再检查原句是否支持结论。合法 ID 但语义不支持时拒绝事实写入；保留原输入与草稿，允许编辑重试。否定、假设、他人叙述不能靠词面相似判断真实。

## 确认与控制

本例不应展示“曾管理20人”的可直接接受候选。若提出“尚无团队管理经历”，必须并列显示用户原句、解释否定含义，默认不选中，并允许编辑或放弃。保存知识与确认个人事实使用独立操作。确认提交时在事务内复核账号、输入版本与来源有效性并去重；账号切换或输入修改后，迟到候选作废并重新生成。

关闭 Memory 要在实际模型请求入口移除事实和复用素材，而非隐藏卡片；知识库开关独立生效。删除事实应同步影响检索、缓存、摘要与同步删除状态，避免旧设备恢复它。历史结果可保留必要来源解释并标注已删除，不得再当当前事实召回。切换账号清空活动上下文与旧候选绑定。明确原件与文本的外发策略；已有离线承诺须保留本地手工整理，否则保持草稿与重试即可。

## 待执行正反例

正例：“我管理过5人”仅在展示原句并确认后入库；同账号相关任务能检索。反例：模板第一人称、当前否定、假设、他人故事、AI 示例、伪造 ID、合法但不支持结论的 ID 均不得自动入库。另测确认期间切换账号或改输入、Memory 关闭后实际请求体、删除后的新请求及同步恢复、文档内越权命令。所有用例尚未运行；人工确认也可能出错，本设计提供可追溯控制，不承诺自动证明事实真实。
