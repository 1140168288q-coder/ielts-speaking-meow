# 可取消且状态真实的供应商降级

让用户能停止操作、切换内容，并在主服务失败时完成已约定的基本任务。
降级必须改变实际执行路径，而不仅是提示“已切换备用”。

## 输入

- 用户操作与其完成标志，主服务和候选备用服务。
- 各服务的能力差异、可用性检查、超时与实际完成通知。
- UI 状态、正在进行的请求、结果缓存及取消机制。
- 用户能接受的降级损失、等待时间、重试成本。
- 当前实现、失败日志摘要及可重复的故障场景。

先确认备用能力是否满足最小需求；不能用不等价结果悄悄替代关键功能。
真实付费调用和外部变更遵循当前任务授权，不因技能触发自动执行。

## 执行流程

### 1. 拆分可用性的证据

分别记录配置存在、服务可达、最近真实操作结果及结果发生时间。
有密钥不代表可用；进程存活不代表上游成功；历史成功不保证当前成功。
定义状态未知和状态过期时的路由策略，依据用户等待成本选择。
若备用路径足够完成基础任务，启动时未知状态可优先走备用。
若备用结果差异重要，在操作前后清楚说明，不冒称与主服务完全等价。

### 2. 固定能力契约

明确开始、停止、完成、失败和可选进度的含义。
对参数分别标明支持、忽略或不支持；不能假设各 Provider 拥有同样能力。
UI 依赖统一契约，供应商特定字段只在适配边界内转换。
备用能力诊断应能直接调用备用路径，避免测试按钮仍经过主服务。
保留用户原输入或草稿，派生服务失败不能使其消失。

### 3. 设计单次操作的生命周期

为每次操作建立递增版本号、活动令牌或等效取消标识。
每个异步边界之后确认结果仍属于当前操作，才允许应用结果。
用户停止或切换时先使旧令牌失效，再停止当前执行者并启动新操作。
能真正取消传输时取消；不能取消时仍丢弃迟到结果，准确说明资源成本限制。
若多个服务共享音频/渲染等资源，用协调器串行处理资源占用变更。
不要把“等待整段播放或生成完成”放在阻塞停止操作的全局锁内。

### 4. 处理主服务失败

仅在操作仍有效、允许降级且备用可用时进入备用路径。
先释放主服务占用，避免两个执行者同时输出；释放失败时按资源风险处理。
遇到持续失败时采用有界熔断/冷却，避免每次操作重新等待完整超时。
说明熔断恢复方式：时间到期、探测成功或用户显式重试，按现有约定选择。
区分主动取消与服务故障，取消不应触发迟到的备用输出。
主备都不可用时给出明确可恢复结果，仍保留用户输入。

### 5. 对齐实际状态和缓存

UI 状态来自活动执行者，区分等待、执行、暂停、完成和失败中实际需要的状态。
接受请求并不证明已经有声音/图像/结果；可获取时使用真实完成事件。
备用切换后把状态订阅指向备用执行者，旧执行者不能把新操作状态重置为空闲。
缓存键覆盖影响输出的文本/输入、模型/版本、声音/风格及相关参数。
配置变化时可通过缓存键版本或迁移策略避免复用旧输出。
可重建缓存读写失败通常不应使已得到的有效结果不可用。
不可恢复的用户资产不应跟随缓存清理策略自动删除。

### 6. 验证交错操作

用 fake Provider 或已有测试框架控制开始、失败、完成和迟到响应。
覆盖无配置、未知健康、主服务失败、冷却窗口、主备均失败。
覆盖 A 开始→停止→A 迟到，和 A→B→A 迟到，不允许旧结果重新出现。
覆盖备用已开始后的停止，以及旧完成事件不能结束新操作。
涉及系统能力时另记录真实环境验证；假 Provider 不能证明设备能播报或显示结果。
一次正常成功不能替代失败路径验收，重复测试以未解决风险为依据。

## 检查清单

- [ ] 状态区分配置、可达和真实操作结果，未知/过期路由有明确规则。
- [ ] 备用路径实际可执行，参数差异和质量损失有正确表达。
- [ ] 停止及切换令旧结果失效，不会晚到重播或覆盖新输出。
- [ ] 熔断与恢复有界，缓存包含实际影响结果的配置且不伤害原始用户数据。
- [ ] 成功、失败、取消、并发交错均有证据，真实设备能力与模拟验证明确分开。

## 输出格式

交付实现或方案，以及以下简洁说明：

1. **路由规则**：何时主用、备用、直接失败和恢复。
2. **生命周期**：开始、停止、切换、迟到结果和资源释放的处理。
3. **用户可见行为**：等待/播放/完成等状态与备用差异。
4. **验证矩阵**：正常、故障、交错操作、缓存变化及测试层级。
5. **限制**：无法取消的真实请求成本、尚未验证的设备或服务。

阅读 [项目案例](references/case-study.md) 可了解曾出现的长等待、旧音色缓存和假播放状态问题。
案例参数用于解释，不要求照搬 60 秒冷却、Android、TTS 或指定供应商。
