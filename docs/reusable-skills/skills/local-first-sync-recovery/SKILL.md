# 本地优先、同步与恢复

先确保用户已经写入的数据可恢复，再修复失败路径和同步行为。
从真实持久化与数据流建立证据，不用页面状态或成功提示代替保存结果。
将本地备份、云端同步、账号注销和本机删除视为不同操作。

## 输入

从项目和问题记录中收集：

- 当前设备、账号、版本、发生问题的动作，以及最近一次可确认的数据状态。
- 主数据库、文件存储、缓存、身份凭据、同步队列和游标的位置。
- 实体、依赖、主键、拥有者、修改时间、版本、删除状态与历史快照。
- 服务端身份来源、同步协议、幂等语义、冲突策略和离线要求。
- 当前备份格式、恢复策略、旧版本支持范围与已有故障测试。

找不到关键事实时，先做只读调查，不猜测存储路径或删除范围。
需要参考实现与局限时，阅读 [项目案例](references/case-study.md)。
案例已自含解释，使用本技能不需要访问原项目路径。

## 执行流程

### 1. 保全现场并确认数据实际位置

检查运行版本、账号范围、存储是否存在、记录数量和可读性。
先区分“没有数据”“当前账号看不到”“模型配置丢失”“迁移读取失败”。
在任何迁移或恢复写入前建立可验证恢复点，并记录原路径与版本。
只读导出或复制应考虑数据库一致性；数据库副本可能还需要日志文件。
不要通过清空数据库、重装或重新导入来掩盖未查明的数据问题。

### 2. 建立持久化与身份不变量

用户本地操作先可靠落盘，再允许 UI 宣告完成。
存储失败保留编辑内容和可重试入口；AI 失败不撤销用户已保存内容。
记录与其依赖原件的写入使用明确事务，或可恢复的阶段提交协议。
读、写、删除、导出、导入和后台结果写入都检查账号归属。
稳定 ID 必须考虑账号范围，不能让同一文件哈希跨账号覆盖私有记录。
云端拥有者来自已认证身份，不能采用客户端可编辑的 ownerId。
区分本地账号与云端账号的绑定，切换账号后重新验证待提交草稿。

### 3. 防止迟到结果与并发写入覆盖

模型调用前记录输入版本或摘要，以及目标实体和账号。
结果写回时重新读取当前记录；输入已变就不应用旧结果。
采用存储层原子读改写或显式版本冲突，不使用全记录盲覆盖。
同一 UI 流程中的多个实体未必在一个事务里，逐个标注真实原子边界。
不能全局原子提交时，说明部分成功状态、幂等恢复步骤和用户可见结果。

### 4. 让同步具备可重放的失败语义

把待同步操作保存为持久化队列，包含作用域、实体、操作 ID 和基准版本。
网络重试复用原操作 ID；同一个 ID 改了内容应被拒绝。
服务端按实体版本检测冲突，不能让客户端时钟决定所有覆盖顺序。
只删除服务端明确确认应用成功的队列项，保留失败、拒绝和冲突项。
响应缺项、重复项或结构不合法时，不把整批当作成功。
拉取按递增游标应用；本地应用成功后才提交对应游标与版本。
若应用与游标提交分离，必须允许同一远端变更重复应用。
发生冲突时保留双方或暂停应用，提供可解释的恢复/解决方式。
没有冲突解决界面时如实说明，不能把“未覆盖”写成“已解决”。

### 5. 把删除与历史当成数据

离线删除记录需保留可同步墓碑或等价删除事件，带账号、实体和版本。
远端收到删除后增加版本；旧设备更新遇到版本冲突，不可悄悄复活记录。
明确恢复、撤销与重复删除的状态转换，避免把“删除一条排除规则”误当“删除内容”。
只有确认远端已接受后才清理本地待提交墓碑。
设置墓碑保留策略前考虑长期离线设备；不要随意按时间清空。
目录换季、模板更新或知识库替换时保留历史记录所需最小快照。
当前目录可变，历史任务引用不能只依赖一个可能被删除的 ID。

### 6. 分开同步、备份和迁移协议

同步默认只发送产品明确允许的结构化实体，排除凭据、缓存和不应上传的草稿。
原始文件与录音是否上传独立决定；结构化文本也可能包含私密内容。
本地完整备份可包含原件，但应明确私密性、大小和恢复依赖。
恢复前校验格式版本、结构、账号冲突和引用依赖，避免写一半才发现缺文件。
制定同 ID 冲突策略：保留较新、显式合并、另存或拒绝；不能无说明覆盖。
迁移优先增量添加并保留旧数据，坏记录单独隔离，不能连带删除有效记录。
测试旧版真实形状与新空库，不能仅测试最新 schema 的自我往返。
大备份的恢复若不是全局事务，要说明中途失败后的重试和残留状态。

## 验收检查清单

- [ ] 断网、AI 失败和重启后，已保存的用户输入仍存在。
- [ ] 两个账号的读取、写入、删除、同步和相同文件导入互不串扰。
- [ ] 并发写入保留双方独立字段；迟到模型结果不覆盖新输入。
- [ ] 中途退出后同步队列和游标仍在，重试复用操作 ID。
- [ ] 同批部分成功、响应缺项、冲突和网络失败不会丢队列项。
- [ ] 拉取应用失败不会跳过该变更；重放同一变更无重复副作用。
- [ ] A 离线删除、B 旧版本更新、A 恢复联网时不会静默复活数据。
- [ ] 目录或模板替换后，历史记录仍有足够快照可展示。
- [ ] 导入事务故障回滚原件、来源与条目；UI 不报告假成功。
- [ ] 旧备份不会无提示覆盖较新本地内容，缺少依赖先拒绝再写入。
- [ ] 坏记录不阻止其他合法记录读取，原始数据保留供诊断。
- [ ] 完成恢复后重新打开应用核验业务数据，而非只核验导入计数。

## 输出格式

交付结果包括：

1. 发现的数据状态与原因，标明已确认事实和仍待验证项。
2. 持久化、身份、同步、删除和恢复各自的不变量与实际修改。
3. 恢复点、事务范围、冲突策略及失败后的操作方式。
4. 已执行的故障场景与结果，未验证的真实设备或多设备行为。
5. 残留局限，例如没有冲突界面、部分恢复非全局原子或墓碑清理未设计。

不要仅凭单测、备份文件存在或云端 200 响应宣称用户数据已恢复。
