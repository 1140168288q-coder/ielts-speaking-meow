# 场景推演：AI 契约漂移诊断与最小修复

本方案仅依据题设与 ai-contract-reliability 技能及其案例推演；未运行代码、调用服务或验证上线。

## 症状与根因

HTTP 200、finish_reason=stop 只能证明传输成功且模型正常结束，不能证明业务成功。现有线索指向 priority 字段校验：上游已完成，结构化结果在进入业务前被拒绝。另有独立的超时冲突，可能让同一次操作更早在浏览器结束。以脱敏关联 ID 串联页面、真实 Provider、网关、Node 上游调用、完成标志、JSON/字段校验和呈现；只记录阶段、耗时、错误码及字段路径，不记录客服正文或凭证。核对 Kotlin 端与 Node 端版本及契约，确认没有请求前绑定错误或提前返回。

## 最小变更

在 Node 的响应适配边界，先对 priority 做精确归一化：原数字 1/2/3 保持不变，仅字符串 "P2" 转为数字 2，再交由严格契约校验。未获确认的 "P1"、"P3"、"2" 不扩展支持；"urgent"、null、缺失必需字段继续失败，不能补默认值。客户端入口也做运行时校验。更新上游约束可降低漂移，但不能代替校验；已确定的非法结构不盲目重试。

80 秒单次处理已超过网关 65 秒，更超过浏览器 40 秒；重试一次最坏为 160 秒再加退避和开销。为同步链路设置一个覆盖所有尝试、退避及解析的总预算：保留现有客户端时，总预算必须低于 40 秒并留传输余量，各次请求只使用剩余时间；若业务必须等待 80 秒，应改异步任务，或确认可调整全部链路后重新分配预算。明确唯一重试层并传播取消，避免客户端放弃后继续重复工作。

分析前保存当前输入草稿；失败保留输入、已有记录和重试入口，区分本地提示与 AI 结果。状态拆为已配置、当前可达、最近上游验证及最近业务结果，携带时间与失败阶段。历史可用不能覆盖本次失败；在成功和失败出口刷新状态。

## 验证矩阵

| 层次 | 受控用例与通过条件 |
| --- | --- |
| 契约 | 数字 1/2/3、P2 成功；urgent、未确认表示、必需字段缺失被明确拒绝；截断、空正文和非法 JSON 不进入业务 |
| 适配链 | 页面使用真实 Provider 实例，仅替换 transport；断言请求实际发出、参数正确、解析与错误映射一致，覆盖方法绑定 |
| 时限 | 模拟慢响应、退避、二次尝试及取消；总耗时不超预算，重试次数不相乘，错误返回后草稿仍在 |
| 状态 | 先成功后失败；历史验证仍可查，最新业务状态准确变失败，本地回退标识可见 |
