# 雅思口语喵 V2.2.2｜三部分展示视频录制、转场与旁白

规划日期：2026-09-18。代码核对版本：V2.2.2，提交 626b72d。用于替代旧版视频方案的镜头安排；保留旧文件作为历史记录。

本次按当前源码核对入口和功能文案，未实际录屏或完成真机/线上服务验收。正式拍摄以安装包实际界面为准。下列旁白为可直接录制的草稿；涉及结果的句子必须与真实画面一致。

## 1. 总体安排

遵循三个部分：①整体界面；②主要训练过程；③辅助功能。建议先制作约 **6 分 20 秒完整版**，再根据比赛实际限制剪短。这个时长是制作建议，不是已确认的官方要求。

- 00:00–00:35：整体界面，建立产品印象和使用路径。
- 00:35–04:00：一题完整训练，形成影片重心。
- 04:00–06:10：导入、个人语料、个人素材、语料库/RAG、记忆、云端、API。
- 06:10–06:20：一句话收尾。

全片围绕同一位演示者和同一道题展开：**先看怎么练，再看练习留下的内容如何被管理和继续使用。** 第三部分用“支持刚才那次训练的能力”串联，避免变成无关联菜单巡览。

## 2. 开拍前准备

### 2.1 数据与状态

1. 选一个单独演示账号，准备少量可公开内容；不要使用空白账号，也不要导入大量素材。
2. 主案例推荐现有 Hobby 题：Do you have any hobbies? 选本人愿意公开的真实经历；如果使用虚构排练文本，全片案例处标注“演示样例”。
3. 预备：一条相关个人素材、一份短教学笔记、一份小题目文件；让它们能在第三部分形成清楚的区别。
4. 实际跑通同一题：第一答 → 真实反馈 → 两个版本 → 训练小计划 → 第二答 → 确认表达/事实 → 完成页。用真实结果修订旁白，不能要求模型生成与预写台词一字不差的内容。
5. 再录主流程正式素材。辅助功能的演示可以分开录，但主训练镜头使用同一次会话，题目、昵称和回答要连续。
6. 事先确认云端邮箱验证状态、真实 AI/TTS 和同步条件。只展示实际成功的结果；没有另一设备时，不表演“跨设备恢复成功”。
7. 记录版本、设备、日期、实际 AI 等待时长。源码实现、历史测试、当日真机实测是不同证据。

可用的第一答排练文本：

> I like play badminton. I play it with my roommate on Sunday. It make me relaxed.

这段只用于演示设计，不是用户事实。二答由演示者看过实际反馈后自己组织，不能直接复制自然提升版。个人素材可用同一虚构演示角色的经历，并清楚标明演示数据。

### 2.2 画面与声音

- 手机原生竖屏录制，最终横屏 1920×1080、30 fps。手机画面保持比例；旁边放一句短解释。反馈、来源、确认项可以局部放大。
- 使用浅色主题，开启勿扰，隐藏私人通知；固定文字大小、时间显示方式和演示账号。录键盘时注意剪贴板和候选词。
- 录屏保留系统声音。TTS 播放时旁白停下，留 3–5 秒英文原声；先导出一小段确认声音真的录进去了。
- 先录产品操作，再剪画面，最后分段录旁白。每段独立录，开头与末尾各留 1 秒静音。
- 中文旁白约每分钟 220–260 字，仅用于估时。全片留出阅读、点击与 TTS 时间，不追求每秒都有解说。下面短段落之间可以自然停顿，不必填满时间。
- 旁白清楚优先；背景音乐可完全不用。使用时保持很低音量，TTS 出声时进一步降低音乐，不盖住英文。

## 3. 转场规则

**同一操作过程：直接切。** 点击后保留约半秒动作反馈，再切到结果；输入和加载可压缩，标“输入已加速”或“等待过程已剪辑”。保留原始长录像。

**看细节：局部放大。** 用约 0.25–0.4 秒推近反馈重点、来源或确认项，停 2–4 秒，再回到整屏。只裁切放大，不改写 App 内容。

**同一菜单内：保留真实点击。** 第三部分沿复盘中心的标签依次进入，省去长距离滚动，但保留足够导航线索。

**切章节：短标题加一句承接旁白。** 不超过 1 秒的标题卡，或在现有界面上叠加“01 界面 / 02 训练 / 03 积累与连接”。不使用旋转、闪白、三维翻页。

**跨独立演示：明确标注。** 主流程结束后加“功能补充演示”；预先准备的资料加“已导入示例”。不能剪成一个旧结果仿佛是刚才点击新生成的。

声音可以比下一画面提前约 0.3 秒进入，让转场更顺畅。系统播题或朗读期间不要这样叠入旁白。

## 4. 第一部分：整体界面，00:00–00:35

### 镜头 01｜00:00–00:08，首页与产品名

**录制**：应用已打开，首页静置 2 秒；显示产品名和副标题“从一次回答，到下一次更自然的表达”。后期字幕不要盖住主要按钮。

**旁白**：

> 这是雅思口语喵，一款围绕两次回答和个人素材积累的雅思口语训练应用。

**转场**：开始轻触“题库”，直接接镜头 02。

### 镜头 02｜00:08–00:25，四个主要入口

**录制**：按“首页 → 题库 → 复盘 → 我的”顺序，各停 3–4 秒。题库露出 Part 分类；复盘露出四个标签；我的露出账号与同步区域。这里不展开设置项，也不录完整注册。

**旁白**：

> 首页开始练习，题库选择题目，复盘查看记录和积累的资料，“我的”管理账号与学习偏好。

**字幕**：开始练习 / 选择题目 / 复盘积累 / 账号管理。跟随画面一次出现一个。

**转场**：从“我的”回到题库，保留点击，不用炫技动效。

### 镜头 03｜00:25–00:35，把界面介绍接到具体任务

**录制**：题库筛选 Part 1，定位 Hobby，题目在画面中央停 2 秒。

**旁白**：

> 接下来，用一道关于爱好的题，看看一次完整训练是怎样完成的。

**转场**：点击题目，叠加“02 主要训练过程”，进入同一题。

## 5. 第二部分：主要训练过程，00:35–04:00

### 镜头 04｜00:35–00:55，听题与准备回答

**录制**：题目页 → 播放题目 → 保留真实英文声音 → 停止。选择性拍一次手动开始计时，不操作所有计时功能。

**旁白（播题前）**：

> 先听题，再按自己的节奏回答。计时由用户手动控制。

**声音**：随后暂停旁白，保留题目 TTS；声音结束后再继续。

**转场**：轻触答案框，切到输入特写。

### 镜头 05｜00:55–01:20，第一答输入与提交

**录制**：手动输入，或用系统键盘语音输入。保留 3–5 秒真实过程，其余加速；最后完整答案停 3 秒，再点实际提交/分析入口。

**旁白**：

> 用户可以手动输入，也可以使用手机系统键盘的语音输入。提交前先检查文字，AI 分析的是这份答案文本。

**字幕**：系统键盘语音输入——仅在实际使用时出现。不要把应用描述为录音转写工具。

**转场**：保留加载状态约 1–2 秒，再接同次请求的实际结果；等待压缩处标注。

### 镜头 06｜01:20–01:50，重点反馈

**录制**：结果页面整体停一下，再放大实际最重要的两项反馈；每项停 3–4 秒，不快速滚过整页。选择与第一答直接对应的改进点。

**旁白**：

> 反馈先突出最值得改的几个问题。用户可以先处理这些重点，再把建议带进下一次回答。

**补一句具体反馈**：依据实际结果录，例如“这里先修正动词形式，再补充一个具体细节。”只有真实结果支持时才使用。

**转场**：视线落到参考版本区域，用同方向轻滚动或直接切局部。

### 镜头 07｜01:50–02:25，两个版本与试听

**录制**：简单优化版停 5 秒，放大一个改动；切自然提升版，放大一处新增表达或内容。拍一下难度/文本风格选择，再试听 3–5 秒。不要为了展示所有档位重复请求多次 AI。

**旁白**：

> 简单优化版保留原意，先把表达说准确。自然提升版再结合适用资料和个人素材，提供可以尝试的内容与表达。难度和文本风格可以选择，两个版本也都能试听。

**声音**：讲完再试听，旁白暂停。

**字幕**：简单优化：保留原意；自然提升：选择性补充。明确两者均为参考答案，不是用户二答。

**转场**：试听停止后接训练小计划，避免音频突然截断。

### 镜头 08｜02:25–02:45，训练目标与依据

**录制**：打开“本题训练小计划”和“为什么这样安排”，露出实际目标、1–2 个动作和来源。只读一个动作。

**旁白**：

> 本题训练小计划把重点整理成下一步动作，也展示这样安排的依据，帮助用户准备第二次回答。

**字幕**：目标 → 依据 → 行动。可在画面外标“应用根据题型、反馈与素材编排”，不做虚构自主思考日志。

**转场**：点击进入二答，保留真实操作。

### 镜头 09｜02:45–03:20，素材复用与自己重答

**录制**：查看实际匹配的个人素材 → 选择合适细节/插入 → 用户修改组织二答 → 完整文本停 3 秒 → 分析。输入过程可加速。

**旁白**：

> 第二次回答可以参考自己已经确认过的素材。用户挑选合适的细节，再用自己的话重新组织，练习把刚才的建议真正用上。

**字幕**：第二次回答：用户重新组织。没有命中素材时不要假造卡片；改录真实可用素材或跳过插入操作，删掉对应旁白。

**转场**：从二答分析加载直接切同次请求结果，等待剪辑标识与第一答一致。

### 镜头 10｜03:20–03:45，分别确认表达与个人信息

**录制**：修正句候选 → 实际勾选；个人信息候选 → 显示对应来源句 → 分别确认；点击完成。重点保留选与不选的判断过程，不“全部勾选”匆匆结束。

**旁白**：

> 二答结束后，值得保留的修正句和个人信息会分别列出。哪些表达留下、哪些信息进入记忆，由用户自己确认。

**说明**：没有真实错误就没有必要出现修正句；没有个人事实就不制造候选。改用另一个实际完成的独立补充案例时必须标明，不接成同一会话结果。

**转场**：完成提示保留 1 秒，再切完成页。

### 镜头 11｜03:45–04:00，完成后留下什么

**录制**：完成页依次露出两次回答与实际确认成果，最多高亮两个不同点。主流程至此结束。

**旁白**：

> 这次练习留下了两次回答，以及用户确认的表达和素材。接下来，看看这些内容怎样继续被使用。

**转场**：点击复盘，叠加“03 积累与连接”。这是全片最重要的承接，不突然跳到设置页。

## 6. 第三部分：辅助功能，04:00–06:10

开头在复盘画面停约 1 秒，然后切独立功能镜头。每一项都用“实际操作＋结果＋一句价值”讲完，不逐字段说明。

### 镜头 12｜04:00–04:18，导入题目

**录制**：题库的实际导入入口 → 选择一份很短的演示文件或粘贴题目 → 候选预览 → 选择一题并确认 → 显示导入结果。文件选择和解析过程剪短。主片不要演示清空或换季替换。

**旁白**：

> 除了内置题库，也可以导入自己的题目。识别后的内容先预览、再确认，加入后就能进入同样的训练流程。

**转场承接**：“题目可以补充，练出的表达也可以留下。”

### 镜头 13｜04:18–04:33，个人语料

**录制**：复盘 → 个人语料 → 定位刚才实际保存的句子 → 点试听，保留 2–3 秒声音。画面标记与主训练案例的关联。

**旁白**：

> 个人语料保存的是自己愿意再次使用的英文表达，可以回看和试听，为下次回答做准备。

**转场**：停止声音后点击相邻“个人素材”，直接切。

### 镜头 14｜04:33–04:50，个人素材

**录制**：复盘 → 个人素材 → 打开一个真实故事或观点，展示题目/主题关联；可用短插入镜头回顾主流程中的匹配，不再重复输入整段回答。

**旁白**：

> 个人素材保存的是自己的故事、经历和观点。遇到相关题目时，可以取用合适的细节，让回答更有自己的内容。

**字幕**：个人语料＝表达句子；个人素材＝故事与观点。两个标签在这一刻同屏，帮助观众建立区别。

**转场承接**：“自己的经历之外，还可以整理学习资料。”

### 镜头 15｜04:50–05:15，我的语料库 / RAG

**录制**：复盘 → 我的语料库 → 一份提前准备的短资料 → 整理预览/确认 → 展开已确认条目的来源。如果 25 秒放不下，只拍“导入—确认—来源”三个实际状态，中间标等待已剪辑。

**可选补充**：若真实自然提升结果有此资料的来源项，插入 3 秒结果特写；需要明确是对应同次资料检索的实际结果，不是随便一张来源图。

**旁白**：

> “我的语料库”用于整理教学和表达资料，保留内容来源。练习时，系统按题目检索相关知识，为 AI 提供参考。这就是这里的 RAG：先找到适用资料，再辅助生成反馈。

**边界**：不要讲成“上传就训练出专属模型”，也不要把资料里的第一人称经历当作用户事实。无需把 RAG 英文全称塞进旁白。

**转场承接**：“资料提供知识，记忆关注当前用户的学习积累。”

### 镜头 16｜05:15–05:35，长期记忆与控制

**录制**：从实际记录区域展开记忆面板，可通过“点开，看看自己走了多远”定位；展示刚才确认的事实或相关历史。再切“我的 → 长期了解与隐私”，露出“在训练中使用长期记忆”“AI 分析时自动匹配可用素材”。

**旁白**：

> 长期记忆来自当前账号的练习、表达和确认素材。用户可以查看已确认的信息，也可以控制是否在训练中使用这些记忆。

**可选操作**：使用演示账号关闭再开启，保留保存成功状态。不删除真实记录，不把“关闭使用”讲成“已经删除所有历史资料”。

**转场**：保持在“我的”，轻滚到云账号与同步区域。

### 镜头 17｜05:35–05:55，云端账号与手动同步

**录制**：使用已验证邮箱的专用演示账号 → 查看同步范围 → 勾选确认 → “确认并开始同步” → 实际成功提示。邮箱脱敏。注册、收邮件和等待放片外完成。

**成功时旁白**：

> 云账号提供手动同步能力。用户查看范围并明确确认后，再同步练习记录和相关资料，让数据管理始终有清楚的操作边界。

**未完成同步实测时替代**：只展示范围与确认入口；旁白改为“这里提供云账号和手动同步入口，用户可以先查看范围，再决定是否同步。”不能剪入假的成功提示。

**转场承接**：“云端也负责连接文本分析与自然朗读服务。”

### 镜头 18｜05:55–06:10，API 接入与服务状态

**录制**：我的 → 设置 → “AI 反馈与自然音色” → 按实际页面展开连接详情，展示文本分析/自然朗读状态。可补录“验证上游服务”的实际结果；剪掉等待，保留验证含义。

**旁白**：

> 文本分析和自然朗读通过自建后端接入，普通用户不需要填写第三方密钥。这里可以查看连接情况，并验证实际服务是否可用。

**拍摄边界**：不录环境配置和密钥；正式构建若锁定服务地址，展示只读状态，不演示不存在的用户改 Key 操作。只看到“已配置”或“云端可达”时，不能旁白宣称模型和 TTS 已真实成功。

**转场**：轻淡出约 0.3 秒回到完成页，进入结尾。

## 7. 结尾，06:10–06:20

**画面**：回到本次训练完成页，再叠产品名。无已验证体验链接时不放二维码。

**旁白**：

> 从一次回答，到一次有方向的重练，再到自己的长期积累。雅思口语喵，让每次练习都留下下一次能用的表达。

**字幕**：两次回答 · 持续积累。最后停留 2 秒，音乐自然结束。

## 8. 转场旁白串联表

以下句子是桥接备选，已经包含同义句时不要重复朗读：

- 整体界面 → 主要训练：“接下来，用一道题走完一次完整训练。”
- 训练 → 辅助功能：“刚才留下的内容，可以在这里继续使用。”
- 导入 → 个人语料：“题目可以补充，练出的表达也可以留下。”

## 11. 成片检查

- 全片不看旁白也能辨认当前部分；字幕不盖住按钮、反馈或来源。
- 同次训练中的题目、昵称、第一答、二答和保存结果一致；独立补录明确分段。
- 核心文字在正常播放尺寸能读清；每次点击后有反应时间，不全程倍速。
- TTS 能听清，与旁白不重叠；声道和音量前后一致。
- 等待压缩不伪造响应速度；AI 示例不冒充用户事实；模拟结果不冒充线上成功。
- 个人语料、个人素材、我的语料库、Memory 四者讲清楚但不重复解释。
- 不出现应用内录音转写、发音评分、Band Score、真实支付或未实现自主 Agent 的错误表述。
- API 部分说明 Backend 接入与状态，不展示第三方 Key；云端同步按真实结果描述。
- 保存完整原始录屏、成片、字幕和录制说明，导出后从头播放一遍再交付。
