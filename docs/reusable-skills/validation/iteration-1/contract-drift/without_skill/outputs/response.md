# 契约漂移与超时：最小修复方案

以下是场景推演和待执行验收方案，未运行产品、调用网络或真实 API，也未证明任何修改已上线。

HTTP 200、finish_reason=stop 只说明上游请求完成，不能证明业务结果通过校验。现有直接证据指向 priority 字段不兼容；超时预算又构成独立故障：客户端 40 秒、网关 65 秒，都可能早于服务端一次 80 秒完成，更无法覆盖重试。页面显示“可用”可能混淆配置、连通和业务成功，应先核对状态来源。

最小修复放在服务端的上游适配入口：仅把负责人明确认可的字符串 P2 映射为数字 2，再交给原有严格结构校验。保留数字 1/2/3；urgent、越界数值及其他未经确认格式继续拒绝，不能取默认优先级，也不扩大映射到 P1/P3。其他字段继续完整验证。记录脱敏的失败阶段、字段路径、关联请求号和耗时，避免记录用户全文、凭证或完整供应商响应。

统一端到端预算，例如客户端 70 秒、网关 65 秒、服务端总预算 55 秒；服务端每次最多 25 秒，两次调用加退避、解析共同不得超过总预算。数值需依据实际延迟验收，不能只延长页面等待。仅对适合重试的暂时错误执行一次重试；非法结构不盲目重试。取消后的服务端行为和迟到结果也需明确，防止页面重复提交引起重复调用。

答案提交前先保存到本地，并关联操作标识；请求失败、取消、切后台或重开页面均可恢复。恢复不自动重发分析。界面分别显示“答案已保存”和“AI 分析失败，当前为本地提示”，不能把保存成功写成 AI 成功。

状态至少分为已配置、服务可达、最近真实分析成功及时间、最近失败及原因。不能仅凭健康检查成功展示 AI 已验证；调用结束后刷新真实结果状态，并防止旧成功覆盖本次失败。

| 验证层 | 输入或条件 | 必须观察的结果 |
|---|---|---|
| 适配与校验 | 数字 1/2/3、P2、urgent、越界和缺字段 | 合法通过，只有 P2 转成 2，其余拒绝 |
| Provider 集成 | 真实客户端 Provider 对接受控假服务 | 检查路径、请求体、响应解析、超时和错误转换 |
| 故障时序 | 慢响应、重试、网关超时、迟到结果 | 总预算生效；无重复展示或静默覆盖 |
| 保存与界面 | 失败后退出再进入 | 答案保留，本地提示与 AI 状态分开 |
| 上线验收 | 正式版本实际分析 | 请求号贯穿客户端、网关、服务端；返回通过完整校验且页面展示成功 |

现有只 mock analyze() 的页面测试不足以覆盖 Provider 契约。上述假服务测试只能支持实现正确性；上线结论还需要部署版本、正式地址、实际调用及页面结果对应证据，本次均未执行。
