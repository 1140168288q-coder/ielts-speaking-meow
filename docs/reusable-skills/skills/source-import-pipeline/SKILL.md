# 保持来源可追溯的内容导入

把来源、解析器、校验器、生成产物和人工审阅连接起来。
让异常显式可见，避免用看似合理的生成内容掩盖缺失来源。

## 输入

- 来源样本、格式、来源授权范围及预计更新频率。
- 下游字段契约、稳定标识和实体间关系。
- 当前解析器、最近有效产物及已有校验或人工审阅基线。
- 允许的规范化规则、可缺省字段与必须忠实保留的字段。
- 导入用途：替换内置内容、合并用户数据或生成离线资产。

读取样本后再选解析方法；图像/扫描文件的识别质量与文本型文件分别评估。
只询问会改变合并、删除、来源信任或字段语义的缺失决策。

## 执行流程

### 1. 定义导入契约

列出必需字段、可选字段、类型、长度、枚举和跨记录关系。
明确稳定 ID 的来源；不要因清理显示文本就无意改变历史引用。
区分“实体 ID 唯一”和“文本不能重复”，真实重复内容可能合法。
明确更新是替换、追加还是合并，以及不再出现的旧实体如何处理。
若涉及用户已有内容，先设计历史引用与恢复，再写入新数据。

### 2. 固定可追溯输入

从同一份实际解析的源字节计算文件指纹，记录来源名与必要版本信息。
区分来源版本、产物结构版本和解析器版本；其变化原因不同。
使用已有版本控制或备份保留最近有效产物。
不要把私有来源文件、访问凭据或未获授权的原始材料自动加入仓库。
若源名不能可靠确定期间或类别，要求显式元数据或给出待确认状态。

### 3. 先解析到候选结构

将输入解析、规范化、语义校验与正式写入分开。
解析时保留必要的页码、行号或实体来源，方便定位异常。
规范化仅修复有证据的排版/OCR 问题，并为易误伤规则准备反例。
缺失正文、关系或提示时返回缺失，不能编造通用语句来满足 schema。
若任务允许 AI 补写，单独标为生成建议并经约定确认，不冒充来源原文。

### 4. 在写入前拒绝不可信结果

同时校验以下层次：

1. 字段形状：类型、必填、值域、未知字段策略。
2. 单条语义：残缺标题、目录/页眉混入、截断、控制字符等。
3. 集合完整性：稳定 ID、实体数量、分类分布与来源覆盖。
4. 关系完整性：悬空引用、重复边、双向关系及允许的基数。
5. 版本对应：来源指纹、审阅基线、解析器版本与输出元数据。

数量阈值来自本来源特征，不能复制另一项目的固定下限。
异常需要阻止发布还是仅提示，按其对下游正确性的影响决定。
缺失必需内容、破坏引用和来源不符通常应阻止写入。
对确实允许的重复、不同关系数量等保留合法测试样本。

### 5. 审阅并提交产物

输出字段/数量/关系变化摘要，抽查变化最大处及历史故障处。
生成器不能自行改写“预期来源指纹”和人工审阅后的正确性基线来让测试通过。
校验通过再写入；需要文件级抗中断能力时采用临时文件加原子替换或等效事务。
“解析失败保留旧文件”和“写入中断仍原子安全”是不同保证，分别验证。
保持生成产物可再生，不手改生成结果补丁，也不在业务界面写来源版式特判。
记录产物来源、版本、数量和审阅者/审阅依据，按任务授权发布或仅留待审阅。

### 6. 处理新版本式失败

定位第一处语义错误，判断是来源缺失、解析适配失败还是契约变化。
只修对应边界并加入失败样本；不能靠降低全部校验绕过异常。
在两个不同修复尝试仍无法建立可靠对应时，保留旧产物并说明需要的新样本或来源。
这个停止点约束不可靠替换，不禁止继续只读诊断或处理独立任务。

## 检查清单

- [ ] 指纹来自实际解析的源字节，来源、结构和解析器版本可区分。
- [ ] 候选结构在写入前校验；异常输入不会覆盖最近有效结果。
- [ ] ID 与关系完整，合法重复和可变关系数量没有被误拒绝。
- [ ] OCR 修复有正反例，来源缺失不会被生成内容静默填满。
- [ ] 人工审阅基线独立于生成器，更新可重现且历史引用仍可解释。

## 输出格式

交付生成产物及一份导入记录，或在只读任务中交付相同结构的方案：

- **来源**：文件/数据集标识、指纹、覆盖范围和授权边界。
- **生成**：解析器版本、产物格式版本、执行入口。
- **变化**：新增/删除/修改数量、关系变化及异常定位。
- **质量**：结构校验、语义抽查、回归样本和人工确认点。
- **提交状态**：已写入/保留旧版/等待来源，实际保证与剩余限制。

了解通用补写掩盖解析失败的真实案例时，阅读 [项目案例](references/case-study.md)。
案例路径只是溯源，不要求目标项目采用同样的库、阈值或业务分类。
