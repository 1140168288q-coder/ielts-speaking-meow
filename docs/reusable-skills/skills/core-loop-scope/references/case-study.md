本案例来自雅思口语喵，证据读取于 2026-09-20。以下代码路径是原项目内溯源，脱离原仓库也可使用本技能；它们不是运行依赖。

没有查到足以证明“因 STT 准确率差、费用高或延迟高而退役”的决策记录。可推断替代后依赖面缩小，但不能写成已证实的产品动机，也不能推广成“AI 应用应该移除 STT”。

## 当前实现与可复用方法

- 新流程仍服务单题两次回答及个人语料收录：`AGENTS.md:9-18`；文本提交及持久化协调：`src/application/practiceService.ts:56-126`。
- 历史结构保留 `stt` 来源只为读取，新回答为 manual/edited；新答案 audio 可为 null：`src/domain/models.ts:393-415`。
- 当前 Android 清单仅列 INTERNET 权限：`android/app/src/main/AndroidManifest.xml:10`。这证明当前清单状态，不等于所有历史二进制均无录音权限。
- 不自动计时、同键停播、切换先停旧声等由交互测试表达：`src/features/practice/PracticeFlow.text.test.tsx:161-272`。
- 未配置 Text AI 时进入本地手工模式有测试：`src/features/practice/PracticeFlow.text.test.tsx:686`。

可迁移做法是把“替换能力”落实到全链路，同时保留用户已有资产；不是仅删除一个按钮，也不是为兼容而继续生成已退役的新数据。
